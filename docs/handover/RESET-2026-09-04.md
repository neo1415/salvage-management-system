## Shared Storage Incident

Staging has a separate database, but shares the Cloudinary account with production.
This dependency was checked too late, after media deletion had begun. Seven files
referenced by staging are unavailable: one profile/selfie image and six KYC documents.
The staging database was not modified. The six protected production/local accounts
and their retained media were verified intact.

Cleanup was paused when sharing was discovered. Cloudinary backup restoration was
attempted for all seven references; each returned `no_backup`. Direct URL recovery
also failed with HTTP 404. The files require replacement from their original sources.
Staging references are now included in the cleanup protection check. Production and
staging should use separate media accounts or explicit environment-scoped folders
before future environment resets.

## Boundaries

This reset does not erase third-party payment/KYC provider records, email inboxes,
Sentry events, provider-managed historical backups, or offline drafts/browser storage
on other devices. Do not resync old offline drafts into the reset database.
Staging database records remain unchanged; the shared-media incident above must be
resolved separately. No deployment was performed.

The reset execution script is deliberately tied to the inventoried production target
and pre-reset count of 1,149 users. It refuses a second run against the reset database.
